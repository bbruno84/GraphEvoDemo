# V09 graph and file laboratory — physical-device result

On 2026-10-26, a signed Development build made with Xcode 27.1 ran on a
physical iPad (iPadOS 27.0) and a different-account iPhone XR (iOS 18.7.10).
The direct-framework V09 fixture used new private/shared stores and synthetic
data. Graph A and control B each had a root, two Entity equivalents, a
Relationship equivalent and an Action equivalent. Owner-only shares placed A
and B in different zones. After a private invitation, XR recovered exactly A
in its shared store; B remained owner-only.

The owner added a 512-byte and then a 10 MiB native binary attachment to A.
XR recovered both with matching metadata, SHA-256 and share identity. XR
replaced the 10 MiB bytes; the owner recovered the replacement after 222
seconds of bounded observation. XR deleted that file; the owner recovered its
absence after 109 seconds, with the small attachment and B intact. These
windows are observations, not CloudKit completion or latency guarantees.

A first participant graph-add stage called `share(_:to:)` separately for
three unconnected new objects. The Entity acquired A's share, but the stage
then reported `NSCocoaErrorDomain:134410`; the Relationship and Action
remained unshared and unlinked. Its reserved ticket and partial fixture were
not replayed. A new run used one `share(_:to:)` call for all three objects
before linking them. XR saw A8; the owner recovered A8+B5 with the exact
relationships and A zone. XR edited an existing A entity; the owner recovered
the edit after 102 seconds. The owner deleted the three added objects; an XR
read-only reopen recovered A5, the retained edit and no B.

A third fresh run scheduled disjoint edits on A's two existing entities for
the same future start time. Both devices reached the waiting phase before the
deadline, then saved their local changes. Each independently recovered the
exact combined state, with both new values, A's share identity and the B
control unchanged; both final reports were exact with no errors. This tests
coordinated local writes and eventual convergence, not a same-object conflict
policy or proof that a remote import overlapped either save. An earlier
unscheduled attempt was invalid: the participant edit reached the owner before
its baseline preflight, so the owner never reserved a write ticket.

An owner invitation preflight initially found records without all reopened
share metadata. The laboratory now waits for complete metadata before
reserving a write. A read-only XR opening after the final graph deletion
failed once before a snapshot; a separate read-only opening succeeded. The
native error's cause was not identified. Raw reports and protected transport
envelopes remain outside the repository. No production store, account
setting, local network or CloudKit schema outside the authorized Development
container was changed.

This result supports a native shared-graph and file route under the tested
conditions. It does not validate a final GraphEvo 2 schema, streaming,
selective download, offline reads, cross-share relationships, cycles,
optional missing endpoints or app/extension concurrency.
